# marketplace-plugins - how to work in this repo

This is jakub's Claude Code plugin marketplace (README.md is the user-facing tour). The repo root holds the marketplace manifest at `.claude-plugin/marketplace.json` (marketplace name `jakub`) and shared docs; everything else is a self-contained plugin under `plugins/`. Install strings are `<plugin>@jakub`.

The charter you already have in context says how we build. This file is only about what's specific to editing the plugins themselves.

## Versions and publishing

Each plugin has one version, written in up to three places that must agree: `plugins/<name>/.claude-plugin/plugin.json`, its entry in the marketplace manifest, and `plugins/<name>/.codex-plugin/plugin.json` when the plugin ships one. The marketplace entry is the number that matters, because both plugin managers name the cache directory after it. A Codex manifest exists only where Codex needs it, for a `hooks` or `mcpServers` pointer; a skills-only plugin (grill) has none, since Codex discovers `skills/*/SKILL.md` on its own. There is no catalog version. `scripts/smoke-plugin-manifests.mjs` asserts the mirrors agree, that a plugin with Codex hooks or an MCP server carries a Codex manifest, and that every hook script both `hooks/hooks.json` and `hooks/codex.json` point at exists.

Installs pull from the pinned GitHub clone, never from this working tree. To test a change: commit, push, then `claude plugin uninstall flow@jakub && claude plugin install flow@jakub`. Hook scripts can be exercised without a reinstall - `echo '<json>' | node plugins/flow/hooks/scripts/no-backlog-guard.mjs`.

Desktop and claude.ai bridge sessions load plugins from service-pushed snapshots with hooks stripped, so a bridge session never sees the charter or the guards; don't debug "the hook didn't fire" from one.

Adding a plugin: `plugins/<name>/` with a `.claude-plugin/plugin.json`, plus an entry in the manifest's `plugins` array with `"source": "./plugins/<name>"`. Plugins don't reach into each other's files - flow's prep stage uses `grill-with-docs` when it's installed and falls back to an inline grill otherwise, and that one-way, soft dependency is the model.

## flow

`plugins/flow/charter/charter.md` is hand-authored by jakub and is the source of truth. The SessionStart hooks deliver it to every session wrapped in `<flow-charter>` tags, which the global CLAUDE.md checks for. There are two hooks because Claude Code caps one hook's stdout at 10,000 characters and swaps anything larger for a 2KB preview plus a file path; `hooks/scripts/inject-charter.mjs` splits the file at the `## ` heading nearest the middle and prints a warning line if either half passes 9,000. Keep each half under that, or the session silently runs on a fragment while the presence check still passes. It's prose to a capable colleague, and it should stay that way. Every line costs context in every session, so anything that isn't true in every session goes somewhere else. The charter reaches the main session only - subagents get CLAUDE.md and the hooks, not the charter - which is why a seat is handed its rules in the one file it already reads.

The charter is host-neutral: it marks a role with `[[role:<id>]]` instead of naming a mechanism, and a third SessionStart hook delivers the host binding profile from `charter/profiles/<host>.md`, where each role gets bound. Nineteen roles: six host roles (`sub-seat`, `context-inheritance`, `search-seat`, `human-choice`, `pipeline-entry`, `artifact-publish`) and, since 0.34.0, thirteen seat roles in a table in the charter's model-selection section, each with floors against the rankings table (`intelligence >= 8`, `effort >= high`, `family: other`, `classifiers: none`; a cell written `4/7` scores at default and at max effort). A profile's seat-role section opens with the rankings table's model name and an effort, and the lint reads exactly those two, so a binding under its floor fails. A stage body names a role in backticks and never a model. `human-choice` is the one the stages lean on most: on Claude it is the in-turn structured question, on Codex it is a suspended turn, and whether asking ends the turn decides which forks a stage asks at all. `scripts/smoke-charter-conformance.mjs` checks that both profiles bind exactly the marked set with prose under every heading, that every seat-role binding meets its floors, that no stage file writes a role marker or heading, and that the charter halves and the profile hold under the byte caps when the real injector scripts emit them. Profiles also ride delegated-seat instructions, built into the delegation bundle.

Codex uses `hooks/codex.json` and one `inject-charter-codex.mjs` handler. Its context limit is large enough to keep the current charter inline, and one handler preserves order. Flow's shared `lib/hook-policy.mjs` owns protected-file and publication policy; Claude and Codex adapters own their different tool inputs and output decisions. Never return Claude's publication `ask` result to Codex: Codex CLI treats that unsupported value as a hook failure and lets the command continue (observed on 0.149.1, still true on 0.152.0), so its adapter must deny and direct the human to publish manually. If a later Codex gains `ask` support, that adapter can retire.

`plugins/flow/seat-contract.md` is the rules a write seat follows, and it has one copy that counts. It sits at the plugin root because the agent loader validates `agents/` recursively and warns on a file with no frontmatter. `agents/implementer.md` opens with the claims only a Claude seat can make and then repeats the contract byte for byte below a sentinel comment; a delegated seat gets the Containment section alone, built into the delegation bundle. `scripts/smoke-seat-contract.mjs` compares the tail with the contract byte for byte and proves the check can still fail with an inline one-character drift.

Doctrine lives in two places and no more. The charter holds what must be true in every session; the stage bodies hold the steps a stage executes. If something appears in both, delete one copy. The skill under `skills/flow/` holds what neither needs at runtime: setup, the doc stack, the ambient crons and hooks, the label contract, and the drift audit.

### Stages

All three pipeline commands are stages, and each stage is one file: `skills/prep-stage/SKILL.md`, `skills/issue-stage/SKILL.md`, `skills/land-stage/SKILL.md`. The body is host-neutral prose that names no host and no host-only tool. It ends with a `## Host mechanics` section holding exactly two subsections, `### Claude Code` and `### Codex`, and those carry only what genuinely differs: where the argument comes from, which native seats and models play each leg, how the cross-family bridge is reached, how the seat contract travels to a writer, how a running seat is reached or that it cannot be, what the escalation ping is, and on land how the merge is issued. The human-choice binding is not repeated there; it is a charter role. The old shape - a `[[gate:]]` marker per checkpoint bound in two profile files per stage - was retired 2026-09-01: 21 of its 39 bindings read "no host difference", and the doubled prose had already drifted once on the trust-fork checkpoint.

`commands/prep.md`, `commands/issue.md` and `commands/land.md` are thin aliases: frontmatter with the tool allowance, one heading, one sentence pointing at the skill and `$ARGUMENTS`. Codex ignores a plugin's `commands/` directory, so there the human names the plugin-namespaced `prep-stage`, `issue-stage` or `land-stage` skill; `agents/openai.yaml` beside each sets `allow_implicit_invocation: false` because a stage that merges, opens issues, or spawns write seats must never start itself, though that suppression is unverified on the plugin-loader path and the human is the actual gate.

`scripts/smoke-stage-conformance.mjs` finds stages by structure (every `skills/*-stage/`) and checks, per stage: the frontmatter keeps model invocation off, the host-mechanics section has exactly the two subsections with prose under each, the body above it contains no host word, the Codex metadata keeps implicit invocation off, and the alias is the one-sentence shape with an allowance line. Its negative cases are inline strings, so a green run also proves the checker can still fail. There is no fixtures directory.

On Claude the merge is a pre-approved `gh pr merge --squash` with no per-command prompt: the gate is the human's own `/flow:land` invocation plus the stage's CI-green and unresolved-thread checks, upstream of the command. On Codex it is a denied merge command plus the `land-merge.mjs` executor.

### Executors and guards

The Codex merge is a deterministic executor, not a checked command. `.flow/managed` is a committed marker that opts a repository into flow's merge enforcement; in a repository that has one, `publish-guard-codex.mjs` denies every merge command it can recognize and names `scripts/land-merge.mjs` in the denial, and in a repository without one it gates no merges at all. The executor takes a pull request number and the head SHA the stage's gates ran against, and nothing else; its authorization is the same as the Claude path's - the human explicitly asked to land and the stage's gates passed. It derives the host-qualified repository from the origin remote, reads the head SHA, state, draft flag and base branch from GitHub, refuses if GitHub's head is not the one it was handed (the PR moved after the gates), refuses armed auto-merge or merge-queue states, and runs `gh pr merge` from an argv array with `--match-head-commit` pinned to that verified head. The guard's command classification is a coarse tripwire whose only real requirement is that it never matches the executor's own invocation, and `scripts/smoke-release-path.mjs` asserts both halves against throwaway repositories with a fake `gh` injected in process.

Claiming an issue is the pipeline's other deterministic executor, `scripts/issue-claim.mjs`. Two issue-stage runs on one issue both see a green re-read of the assignment and the label, so keeping them apart is a tag push decided server-side. The helper creates `refs/tags/flow-claim-issue-<N>` on origin without force, and git's ref advertisement lets exactly one racer create it. It reads the porcelain flag column and not the exit code, because pushing at a tag that already points at the object you were about to push also exits 0, and that is the ordinary shape of losing this race. `scripts/smoke-issue-claim.mjs` races it against a bare repository under `mktemp` - no network and no fake git, since the guarantee is git's own and faking it would test nothing. The `claim` verb composes acquire, the live-run scans, the worktree and branch at the verified base, the push, the assignee and label move, and the release into one command that prints one JSON line; `scripts/smoke-issue-claim-verb.mjs` drives it against a bare origin with a fake `gh` injected in process.

`scripts/land-gates.mjs` is the land stage's read-only gate executor: it re-derives every fact the gates inspect (PR state, default-branch base and stacked children, the CI rollup partitioned with the base branch's known-flakes allowlist, every review thread over paged GraphQL, linked-issue recovery, the follow-up draft, auto-merge and merge-queue arming) and prints a JSON verdict with `stops` and `attention`. It mutates nothing; the rerun valve, the follow-up ack, child retargeting and the merge stay with the stage. `scripts/smoke-land-gates.mjs` drives it against a fake `gh`.

`scripts/tree-snapshot.mjs <path>` prints the four digests the prep and issue stages compare around every read-only seat (porcelain status, unstaged diff, staged diff, and every untracked unignored path by name, type, mode and content). The stages used to spell the pipeline out inline, twice, with tools outside their allowance.

The git guard has two modes. Interactive mode denies the hook-bypass flag, trailers, bare force-push and the narrow destructive set, matched against the command with quoted strings and heredoc bodies stripped. Cron mode (whenever `FLOW_CRON_JOB` is in the env) is a fail-closed grammar over every command, git or not: simple commands joined by `;`, `&&`, `||`, newline or `|`; command words from a short allowlist (`git`, `gh`, `node` with a script path and never inline code, `bash` or `sh` with a script under the plugin root, `claude`, `gripe`, and a few harmless words); quoted strings only as whole argument words or glued after `--opt=`; pipes only into a fixed set of read-only filters; redirection only to `/dev/null` or a descriptor; no `$` outside single quotes, no backslash, backtick, grouping, lone `&`, or assignment prefix; git segments additionally deny-by-default on subcommand, refuse `-c`, `--config-env`, `--exec-path`, URLs, transports and quoted refspecs, and sanctions are ignored. Quoted argument words drop to a placeholder before the git classifier reads the command, so a report that quotes a git write is prose. Do not go back to a scanner that blanks what it recognizes: two review rounds found eleven ways past one. Both modes have their own cases in `scripts/smoke-git-guard.mjs`; the cron cases exist because the lint job spent eight nights denied for quoting the git commands it was reporting on, and then because the first fix let quoted executable words through.

The scheduled jobs are three files each: the prompt in `skills/flow/cron/<job>.md`, the allowlist in `scripts/flow-cron.mjs`, and the unit pair in `skills/flow/templates/systemd/`. A job's authority is the allowlist plus two mechanisms, never the prompt: git-guard's cron mode and `scripts/lint-actions.mjs`, the deterministic executor that alone performs the lint's worktree/branch mutations after re-deriving the safety conditions from fresh state; widening what a job may do is an edit to `flow-cron.mjs` and a version bump, and the prompt's "standing permissions" paragraph must match it. The report is the last main-thread assistant message starting with `# flow `, not the session's final message, and `scripts/smoke-flow-cron.mjs` holds that. Test a prompt change without installing anything: `CLAUDE_PLUGIN_ROOT=$PWD/plugins/flow FLOW_STATE=/tmp/x bash plugins/flow/scripts/install-cron.sh run lint`. The installed timers resolve the plugin through `installed_plugins.json`, so they pick up a new version at the next reinstall with no further step. The jobs are Claude-hosted whichever host orchestrates the pipeline, and that registry is Claude's user scope alone, so `flow@jakub` has to be installed at user scope (`claude plugin install`'s default) or the launcher resolves nothing. `install-cron.sh` runs every launcher-independent check before its first write and names that requirement when it fails.

`scripts/worktree-audit.sh` is ported from pstack (see `plugins/flow/NOTICE`); unlike grill's vendoring it is a fork, edit it freely.

Ad-hoc Workflow scripts are plain JavaScript: no TypeScript syntax, and no `Date.now()`, `Math.random()`, or argless `new Date()`, because they break resume.

Agent defs under `agents/` don't pin a model; the orchestrator sets model and effort at spawn. The explicit `tools:` list is load-bearing - a subagent without one can call Agent, and `implementer.md` relies on not having it.

### Delegation

Facts that go stale (model pricing, the Codex App Server protocol) carry an as-of date. Re-verify anything older than a quarter, and re-verify the host capability table on every CLI bump since both CLIs ship weekly. The delegation contract lives in `plugins/flow/docs/DELEGATION.md` and `plugins/flow/src/delegation/`, validated against Codex CLI 0.152.0 as of 2026-09-01. Delegation requires Linux with cgroup v2 and a working systemd user manager because every provider runs in a transient scope; there is no other platform path.

`plugins/flow/capabilities.json` is the hand-maintained host capability table the issue stage's write-seat preflight reads through `delegation_doctor`. It is a plain file on purpose: editing it needs no rebuild. The doctor computes `hostCapabilities.drift` from the installed CLI version against the table's `verifiedAgainst` - `match`, `newer`, `older`, `unknown` - and the stage stops only on `older` or `unknown`; `newer` is a journal event asking for a re-check, because the table is biased false and a newer host can only have gained capabilities it does not yet claim. The earlier rule compared the two strings for equality in prose and stopped the stage on every routine CLI update.

Two provider smokes cover the contract, and both drive the committed bundle over MCP stdio; neither needs `npm ci`, a Claude account, or network. `scripts/smoke-delegation.mjs` runs the service against a fake App Server and needs Linux with the containment prerequisites. `scripts/smoke-claude-delegation.mjs` runs the Agent SDK path against a fake Claude Code process. `scripts/smoke-bundle-drift.mjs` rebuilds `dist/delegation.mjs` from `src/delegation` and fails unless the committed bundle comes out byte-identical; it is the one script that needs `npm ci` in `plugins/flow/deps`. Every install runs the bundle and never the source, so an edit under `src/delegation` is half a change until `npm run build` in `plugins/flow/deps` regenerates `dist/delegation.mjs` and both go in the same commit. The bundle also inlines the plugin version, the charter, both profiles and the seat contract, so a version bump or a charter edit rebuilds it too.

## gripe

`plugins/gripe/` is first-party, no vendoring. Three layers: `lib/` (`store.mjs` owns SQLite and migrations, `context.mjs` derives repo and session identity, and `gate.mjs`, `failure.mjs`, and `checkpoint.mjs` own harness-neutral noise policy and bounded state), thin hook scripts under `hooks/scripts/`, and `bin/gripe` plus `bin/shim.mjs`, the CLI and the resolver that finds the installed plugin at exec time. Claude registrations live in `hooks/hooks.json`; Codex registrations live in `hooks/codex.json`. The design rationale with the measured claims is `docs/gripe/DESIGN.md`; the reader-side analysis method is the skill under `skills/gripe/`.

`bin/shim.mjs` is the file copied to `~/.local/bin/gripe`, so it is self-contained: node builtins only, no import of anything else in the plugin, because it runs before a plugin root is known. It globs this marketplace's directory in both harnesses' plugin caches (`~/.claude/plugins/cache/jakub/gripe/<version>/` and `${CODEX_HOME:-~/.codex}/plugins/cache/jakub/gripe/<version>/`), skips a version Claude Code has marked `.orphaned_at`, ranks the rest by the version in the directory name, and hands off to the newest. It reads no registry file: the cache directory name is the version the plugin manager wrote, and the one skew ever measured (a stale registry beside a newer cache) is exactly what newest-wins settles. Codex writes no orphan marker, so on that side a removed-but-cached newer version keeps winning until its directory is deleted; that is the documented rollback step. `GRIPE_HOME` is the only override, decided by key presence, and a broken one stops rather than falling through to installed code. Filing exits 0 whatever happens; every other subcommand is honest. The shim carries exactly one `// gripe-shim-epoch: <n>` line and `pointShim` overwrites the on-disk copy unless that copy's marker parses strictly higher, so the epoch bumps when shim behavior changes and never per release. Newest live version under this marketplace alone, the exit split, and the epoch grammar are the contract `scripts/smoke-shim.mjs` holds. Every hook validates `session_id` and `agent_id` before either reaches a filename, on both hosts.

Gripe's Codex checkpoint state is folded from structured PostToolUse events, never the unstable Codex transcript format. Codex does not identify the subagent actor on PostToolUse, so the checkpoint is parent-session state evaluated on main Stop only. Do not add a Codex SubagentStop checkpoint until the event stream can attribute its evidence. PostToolUse also has no reliable failure status (observed on 0.149.1: a Bash command that exited 7 supplied `tool_response: ""`), so Codex records tool-target repetition but does not run the Claude repeated-failure nudge. PermissionDenied and StopFailure remain Claude-only because Codex has no after-the-fact equivalents; a nearby event with different meaning is not a compatibility layer.

Filing must stay free: `gripe add` always exits 0 and never prompts. Any change that can make it exit non-zero or block on input breaks the contract every hook relies on. `scripts/collision-test.mjs` exercises concurrent writers against one database.

## grill

`plugins/grill/skills/` is vendored from https://github.com/mattpocock/skills (MIT), upstream plus four patches. Don't hand-edit the vendored files. A local change is a patch in `plugins/grill/patches/`, so a re-sync stays mechanical: copy the three upstream dirs over, `git apply` each patch in order, bump the SHA in `plugins/grill/NOTICE`. If a patch stops applying, regenerate it, and verify by applying the chain to a fresh upstream copy and diffing against `skills/` - identical or it is wrong.

The patches, in order: lowercase the doc-artifact filenames (`context.md`) and the skill's own reference docs, keeping `SKILL.md`, `AGENTS.md` and `CLAUDE.md` uppercase because the loaders find them by exact filename; route a `grilling` round through the structured question tool when it is in the tool list, and otherwise ask one question per turn with up to 4 numbered options, so the same vendored text works on Codex, with `grill-with-docs` composing through the Skill tool when there is one and by reading its two sibling `SKILL.md` files otherwise; strip the `context-map.md` mechanism out of `domain-modeling`, since we keep the map in a repo's `## Contexts` section and the prep stage forbids inferring "single context" from a missing map file; and let the model invoke `grill-with-docs` on both hosts (no `disable-model-invocation`, `allow_implicit_invocation: true` in its `agents/openai.yaml`). The capability check is inline in the vendored text because a model can read its own tool list.

Grill ships no Codex manifest: Codex finds `skills/*/SKILL.md` by itself, and `scripts/smoke-plugin-manifests.mjs` allows a skills-only plugin that shape.

Three skills is the minimal closure - `grill-with-docs` wraps `/grilling` using `/domain-modeling`. Upstream ships 36 across four buckets; carrying another one is a decision, not a default.

## unslop

`plugins/unslop/skills/unslop/SKILL.md` is vendored verbatim from Lauren Tan's pstack skill in `cursor/plugins` (MIT), no patches yet. If it ever needs one, follow the grill pattern and bump the SHA in `plugins/unslop/NOTICE`.

`hooks/scripts/inject-unslop.mjs` delivers the rules, not the skill description - "Must always apply" in frontmatter is advice the model follows unreliably. One script serves both harnesses in two modes. `session` runs on SessionStart and prints to stdout. `subagent` runs on SubagentStart, reads the hook JSON on stdin, and answers with `hookSpecificOutput.additionalContext`. Plugin-local wrappers live in `lib/rules.mjs`; source-aware skip policy lives in `lib/agent-selection.mjs`. Claude registrations use `hooks/hooks.json`, and Codex registrations use `hooks/codex.json`.

Each mode wraps the vendored body in its own plugin-local scoping note. The session note carves out conversation: the full ruleset for deliverables, rules 26-31 for technical explanations in chat, and the output style wins mechanical conflicts (em dashes, "harness"/"surface") in chat. The subagent note has no such carve-out, because a subagent has no conversational turn - everything it emits, including its report to the orchestrator, is a deliverable and gets the mechanical rules too. It does say the rules never license editing text the agent was asked to reproduce verbatim. Scoping changes go in these wrappers, never in a patch to the vendored file.

The subagent selection policy is the whole cost control: Claude `Explore` and the search fan-outs return file paths and would buy the ruleset once per agent, and `fork` already carries the session block in its copied context. Those skips are Claude-only, because each one is justified by a Claude mechanism; a Codex seat receives the rules whatever its name, until a Codex capture proves a skip safe there too. Everything else is on by default - the point is covering ad-hoc `general-purpose` and `claude` spawns that have no agent definition to carry the rules for them.

Watch the 10,000-character Claude hook stdout cap that forced flow's charter into two hooks. The subagent payload is JSON-wrapped, so it is the larger of the two: 7,786 bytes as of unslop 0.4.1, about 2KB of headroom. Codex's handler uses a 3,000-token inline context limit. A re-sync that grows `SKILL.md` past either bound eats or spills the rules. Measure after any vendor bump: `echo '{"agent_type":"claude"}' | node plugins/unslop/hooks/scripts/inject-unslop.mjs subagent claude | wc -c`.
