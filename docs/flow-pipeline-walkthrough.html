flow 0.9.0 · prep → issue → land

the pipeline, step by step

Three commands, two human touchpoints, everything between them hands-off. Prep is where models argue and the human decides; issue is where models build and models check; land is the only place a merge happens. Every step below shows what it does, how it works, and who sits in the seat.

act i · interactive · the only lane that creates issues/flow:prep — the front door

Takes an issue number or a free-text idea. Output: a design-hardened, ready-for-agent issue — or the work just gets done, or split. Nothing enters the tracker except through here.

1Entry & dedupe

Load the issue, or — free-text mode — search open AND closed issues + PRs first. Closed/wontfix matches surface and stop; nothing gets resurrected, no issue is created yet.

2Scout

Domain docs (AGENTS.md → context.md slices → the 1–3 ADRs this touches), code seams, prior art — then a design-readiness read: what's clear, what's ambiguous, what a cold implementer would trip on.

How: breadth delegated to scoped agents; only paths + seams come home, never file dumps. The main context is the decision layer.

Explore agents · sonnetoutside read · sol

3Triviality gate (the exit ramps)

Fully specified and small → do it now, no ticket theater. Too big for one PR → split into tracer-bullet slices, each getting its own prep pass. Only survivors continue — which keeps the heavy machinery below off quick work.

fable · session

4Design dialectic — where ADRs are minted (new in 0.9.0)

Two blind proposals at the product/architecture level — shape, boundaries, protocol surfaces, trust models. Then each leg critiques the other and returns the strongest version of the disagreement. No averaging: the synthesizer is the human, in the grill.

How: the claude leg designs from the scout's seams; the sol leg designs independently AND hunts spec gaps — what the human hasn't said that an implementer would decide silently. The resolved argument becomes grill material. Code-level joinery (placement, signatures) deliberately stays out: it's drawn at run time against live HEAD, because prep-time design goes stale.

claude leg · opus/highsol leg · high, blind

5Grill

One question at a time, each with a recommended answer (correctness weighted over minimal-change). Agreements from the dialectic arrive pre-packaged; disagreements arrive as questions the human adjudicates. Trust-model forks are ALWAYS presented — runs are forbidden from guessing these, so this is where they get settled cheaply.

How: decisions crystallise as they land — context.md edits and ADRs written inline, stress-tested against glossary and code. This is why the dialectic lives here: a thorough discussion at the moment of minting, with the human already present.

fable asks · sessionhuman decides

6Acceptance criteria — testable by construction

Every criterion names its own evidence: the test, command, transcript, or screenshot that will prove it. "Works well" and numberless "fast" don't pass the front door. Whole set bounded to one PR.

fable · sessionhuman approves

7Finalise

Doc artifacts (context.md, ADRs) committed to main in one docs(...) commit. Issue body rewritten in place into the hardened spec; design trail posted as a journal comment; the label contract validated — including explicit design closure (shape decided, or declared free within bounds) — then ready-for-agent.

fable · sessioncontract lint · sonnet

the 0.9.0 invariant

An issue may not reach a run with an open design question — one anywhere in the spec fails the contract and the nightly lint strips the label. Design debate belongs here, where arguing is cheap and the human is present; a run that discovers open design escalates back through this door.

issue is now ready-for-agent · the human walks away ▼

act ii · hands-off · fable conducts inline/flow:issue-beta — one run, through the PR

No fixed pipeline — the conductor composes the fabric per issue above eight non-negotiable invariants, journaling the composition before work starts and every deviation as it happens. Output: a pushed, reviewed, evidenced PR. Never a merge.

0Claim, snapshot, compose

Atomic claim (assign + in-progress, verify it landed), snapshot the AC section, worktree off origin/main. Then the launch journal comment: which seats, which modes, why — the human audits the composition, not just the outcome.

fable conductor · inline

1Design pass — always on

The code-level joinery prep deliberately left open: placement map, single-source-of-truth declarations + drift guards, API shapes with signatures (streaming vs buffered is decided HERE, on paper), invariant ownership, milestones with per-milestone difficulty, and the "not-alone" list — decisions the implementer may not make without a checkpoint.

How: blind pair — the opus leg frames minimal-change against the actual seams; the sol leg proposes independently and hunts what the spec left unsaid. The conductor synthesizes, resolving disagreement explicitly (a disagreement here costs a paragraph; at review time it costs a fix round). Flexes: widen to three legs (add the fable taste leg) on new subsystems or hard disagreement; shrink to a lone sol pre-flight only when there's no code-design space at all. Never zero — skip to zero and the implementer becomes the architect by default, unreviewed.

minimal leg · opus/mediumblind leg + gap hunt · sol/highsynthesis · conductor

2Implement + shadow (milestone loop)

Strict TDD (red → green → refactor), one milestone at a time, atomic conventional commits. Effort routed per milestone: transcription-grade work at medium (reads the plan literally, scopes tight), subtle-invariant milestones at xhigh.

How: a sol shadow reads commits as they land, accumulating findings silently. At each milestone boundary the conductor triages the pile and hands blocking items over before the next milestone starts — early signal, zero mid-thought interruption. The shadow's watchlist includes the design pass's not-alone list, so structural drift is a checkpoint finding, not just behavioral bugs.

implementer · opus med→xhighshadow · sol/highcheckpoint triage · conductor

3Build gate

The repo's canonical check (just check, cargo + clippy, …), race-enabled where documented, retry-wrapped. An errored, rate-limited, or timed-out run is UNKNOWN — its own state, never a pass.

sonnet · low

4Review fabric (composed width, parallel)

The lenses the conductor composed at launch. Standard: an adversarial seat prompted to BREAK the change (with the demonstration fast lane — a finding backed by a failing test is confidence 100, skips adjudication, and its fix inherits the test), correctness, security, and the per-criterion AC evidence check.

How: at least one seat is always cross-family from the implementer (decorrelation invariant). A refused security seat retries on the other family; a double-null rides out to the human as securityReviewUnavailable — a review that never happened must never read as a review that found nothing.

adversarial · sol/highsecurity · opus/xhighcorrectness · opus/xhighAC check · opus/mediumsecurity fallback · fable/high

5Fix loop → convergence (evidence-terminated)

Blocking findings fixed — parallel across disjoint files, serial otherwise; crit/high fixes at xhigh, the rest at medium (the re-review is the real verification). The loop ends on EVIDENCE, not a counter: one clean cross-family pass for standard work, two consecutive from different seats at a trust boundary or after churn.

How: the final pass carries the breadth backstop — it sweeps the whole diff at file granularity and lists what it read and skipped; any file no reviewer has named since the last fix round is an automatic gap (churn depth never discharges closing breadth). Past ~5 rounds the breaker fires: stop fixing, adjudicate survivors at max effort — real blocker vs reviewer theater, judged by reading the code — and escalate the real ones. The breaker interrupts a human; it never ships silently.

fixes · opus med/xhighconvergence pass · sol/highadjudication · opus/max

6Doc-sync, push, PR

Diff-aware context.md/AGENTS.md corrections, edited in place (docs correct what the diff made false; they don't grow per PR). Rebase, push, open the PR — summary + per-commit changelog, ending in Closes #N.

How: every push is verified by sha comparison (rev-parse HEAD vs ls-remote), never by exit status; the Closes-link is re-read from closingIssuesReferences after creation, never assumed from having written the line.

doc-sync · opus/highpublish · sonnet/low

7Post-push · self ∥ external

Complementary lenses the internal fabric didn't run — test quality, silent failures, type design on sol; comment rot on the cheap-depth luna/max combo — in parallel with external bots (coderabbit et al., ~15 min poll cap; silence never stalls the run).

How: everything triages into one verdict set: fix / noise / already-fixed (stale-SHA findings re-verified against current HEAD first). Two-key dismissal: a medium+ finding is dismissed as noise only when both model families agree it is. Fixes push with sha verification; external threads get reasoned replies naming the fixing commit.

lenses · sol/high + luna/maxtriage · conductorfixes · opus

8Ledger & handoff

Per-criterion evidence table on the PR — verdict + pointer, every entry re-executable from the merged tree (committed test, committed script, committed artifact; journal prose and expiring URLs are not evidence). Then the final read of the PR as it exists NOW: head-sync guard, per-check CI rollup, late-external count, and the coverage report — seats composed vs delivered, by name.

How: CI may be "green" ONLY on a head verified in sync. The final journal comment closes the issue's run record; escalation valves (needs-info / needs-human / needs-rebase) each fire a phone push — blocked runs interrupt the human, nothing else does.

ledger + handoff · sonnetcoverage · conductor

what makes beta beta

v1 (/flow:issue, the stable path) runs this same contract through a fixed 993-line workflow — static fabric table, 3-round fix cap, one difficulty for the whole run. Beta trades the lookup table for a conductor bound by invariants: fabric width, per-milestone effort, and loop termination all flex to the issue, and mid-run tripwires (unmentioned trust boundary, 2× file count, fix churn, hard cross-family disagreement) force a fabric re-think, each firing journaled.

act iii · interactive · the only merge path/flow:land — the human gate

The deterministic closing ritual. Merging is hard to reverse, so every gate reads real state and anything off gets presented, not powered through.

1Resolve + stacked-chain guard

Full PR state read; linked issues recovered even when the Closes-ref is mangled (branch name, title, body — ask before closing nothing). A PR based on another branch doesn't merge until its parent lands; children get retargeted first.

fable · session

2CI gate — per-check, UNKNOWN ≠ clean

The rollup is partitioned check by check; --watch exit codes are never trusted. Known flakes merge through only if listed in the repo's .github/known-flakes.txt. One narrow rerun valve exists for a pre-existing, timing-shaped, non-overlapping single-test failure — once. Red twice on identical code is real: abort.

fable · sessionrollup reads · sonnet

3External-threads gate

Unresolved external reviewer threads BLOCK the merge. Each is fixed (resolve, note the commit), answered (the reply stands — resolve), or genuinely open (fix now or send back through a fix round). Late-arriving reviews are caught here by design.

fable · session

4Escape-hatch ack

If the run drafted a follow-up (cross-crate-refactor scale only — the single exception to no-backlog), the human acks it into a real issue or consciously drops it. Either way the decision is recorded on the PR.

human decides

5Merge + close — prove it

Squash-merge, then read back state == MERGED — never inferred from exit codes. Remote branch deleted; every linked issue checked and closed by hand if the ref didn't do it (parenthetical refs don't auto-close).

fable · session

6Cleanup + memory

Main pulled, worktree retired, local branch deleted, remote-tracking refs pruned, per-worktree resources (test DBs, containers) torn down best-effort. Project memory stamped so finished work is never re-suggested.

fable · session

7Survey

Open PRs with one-word statuses, issues bucketed by lifecycle label, stale state — synthesised into a ranked 3–6 line menu, highest-leverage move first. The human picks; nothing auto-starts.

fable · sessionhuman picks

the through-line

Every gate in all three acts enforces the same epistemics: UNKNOWN ≠ pass. Errored checks are their own state, pushes are verified by sha, merges are read back, evidence must survive git clone, and a review seat that silently vanishes is surfaced — because the one failure this whole system is built to prevent is a check that never happened reading as a check that passed.
