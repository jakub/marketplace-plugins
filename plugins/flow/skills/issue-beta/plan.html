issue-beta: the dynamic run

v1 encodes distrust of the orchestrator in 993 lines of workflow script. Beta replaces the lookup table with a conductor — fable, inline in the session — that composes the run per issue, holds eight non-negotiable invariants, and spends the flat-rate codex seat like it costs nothing. This is the process flow, the decision logic, and the prompts, marked up.

①The mental model

v1 is a pipeline: a fixed FABRIC table maps a size bucket to a set of seats, and a 993-line script runs them in a fixed order with hardcoded caps. It works because it never trusts the orchestrator to decide anything. Beta inverts that.

v1 — the lookup table

  • size judged once, at launch, from issue text
  • FABRIC[size] picks the seats — static
  • FIX_ROUND_CAP = 3 — a counter, not a verdict
  • seats pinned in a table; effort per-seat constant
  • conductor fires a background workflow, then idles

Distrust encoded as structure. Safe, legible, rigid.

beta — the conductor

  • size is a continuous signal; re-thought on tripwires
  • conductor composes the fabric per issue and mid-run
  • fix loop terminates on a clean adversarial pass
  • seats routed by capability table; re-run up when weak
  • conductor is fable, live in the session, the whole run

Trust encoded as invariants. Adaptive, cheaper on easy work, deeper on hard.

why this works now

The charter's capability table rates fable at intelligence 9 / taste 9. A lookup table is what you build when the thing reading it can't be trusted to judge. Hand the same table to a model that can judge, bolt on a short list of things it may never trade away, and the table becomes a floor instead of a ceiling. The bet: taste 9 + rules of engagement > a static map.

②Process flow

The conductor is not running a script — it is making a sequence of routing decisions. The spine below is the default traversal; every node is a place where the conductor may widen, narrow, skip, or loop based on what it just saw. Dot colour = node kind.

work / seat gate (UNKNOWN ≠ pass) loop (evidence-terminated) fork (may ask the human)

0 · Claim & snapshot

Atomic claim (assign + in-progress, verify it landed), snapshot the ## Acceptance Criteria section, worktree off origin/main. Post the composition journal comment — which seats, which modes, why — before any work. The human audits the plan, not just the result.

fable · conductor

1 · Compose the fabric decision point

Read the issue. Is the design already decided (ADR / tight spec)? → skip the design panel, run a pre-flight sanity pass instead. Green-field? → design dialectic. Trust boundary in the diff surface? → pre-arm the 2-pass convergence tier and the security seat now. This is the single richest decision in the run.

fable · high

2 · Design — dialectic (or skip)

When design is open: both families design blind (decorrelation), then each critiques the other, then the conductor synthesizes proposals + critiques + rebuttals into one plan with per-milestone difficulty. When design is closed: one decorrelated pre-flight reconciles spec against real code seams.

opus · medsol · highfable · high (synth)

3 · Implement + shadow milestone loop

TDD, one milestone at a time, effort routed per milestone. A codex shadow reads commits as they land; at each milestone boundary the conductor triages the shadow's accumulated findings and hands blocking ones over before the next milestone starts — early signal, zero mid-thought interruption.

opus · med → xhighsol · high (shadow)

4 · Build gate

Repo's canonical check (just check, cargo, …), retry-wrapped. Errored / rate-limited / timed-out = UNKNOWN, which is its own state — never a silent pass. Failure → fix in atomic commits, re-run.

sonnet · low

5 · Review fabric (composed width)

Parallel lenses, chosen at step 1: adversarial (codex, prove-it-or-drop-it) · correctness (opus xhigh) · security (opus xhigh, + fable fallback on refusal) · AC evidence check. Simplify lens only when there's altitude to drift. Deterministic fan-out → optionally a short ad-hoc Workflow script for resume; adaptive stages stay direct Agent calls.

sol · highopus · xhighfable · fallback

6 · Fix loop → convergence evidence-terminated

Fix blocking findings (parallel over disjoint files, serial otherwise; xhigh for crit/high, medium below). Terminate when a fresh cross-family adversarial pass comes back clean — 1× for standard work, 2× consecutive at a trust boundary. Breaker at ~5 rounds: stop, adjudicate survivors at opus max, escalate the real ones.

opus · med/xhighsol · high (verify)opus · max (adjudicate)

7 · Doc-sync → push → PR

Diff-aware context.md / AGENTS.md updates, edited in place. Rebase, push, open PR with Closes #N — link verified by reading closingIssuesReferences, never inferred. Head-in-sync observed: local sha == PR headRefOid.

opus · high (docs)sonnet · low (push)

8 · Post-push · self ∥ external

Complementary codex lenses (tests, silent-failures, types on sol/high; comment-rot on luna/max) run in parallel with external bots (coderabbit, ~15 min cap; silence never stalls). Triage into one verdict set — two-key dismissal: a medium+ is noise only if both families agree.

sol · highluna · maxfable · triage

9 · Ledger & handoff

Per-criterion evidence ledger on the PR (test + output, command, file:line, screenshot). Final handoff: head-sync guard, CI rollup read from the per-check view (not --watch exit codes), late-external count. Final journal comment with coverage: seats composed vs delivered, by name.

③How it decides

Three decision engines run continuously under the conductor. They are the difference between "a model winging it" and "a model composing to a doctrine."

3.1 · Composition — at launch (step 1)

Signal read from the issueFabric response
Design already decided (ADR link, "do not reopen")Skip design panel → one decorrelated pre-flight (spec vs code)
Green-field / genuine design forkFull dialectic: blind designs → mutual critique → synthesis
Trust boundary in the surface (auth, parsing, shell/SQL, secrets)Pre-arm 2-pass convergence; security seat is headline, not a lens
Spec unusually complete, mechanical shapeImpl seat effort drops to medium (reads plan literally); drop simplify lens
Claims are executable/testableAdversarial seat prompted to demonstrate (fast lane, confidence 100)

3.2 · Re-sizing — mid-run tripwires

Size is not a launch verdict. Any of these forces a fabric re-think, and each firing is journaled as an event:

  • tripwire  the diff touches a trust boundary the issue never mentioned → add security seat + upgrade to 2-pass convergence
  • tripwire  diff exceeds ~2× the plan's expected file count → re-open the size question; possible scope-creep escalation
  • tripwire  fix rounds churn on one area (a fix spawning findings where it landed) → the design is wrong, not the code; re-synthesize
  • tripwire  cross-family reviewers disagree hard on the same code → standing consult, resolve explicitly, never average

plus taste

Beyond the tripwires the conductor may widen on any hunch — and narrow too (a "medium" that turned out mechanical). Narrowing is journaled as loudly as widening; a silently thinned fabric that reads as a clean pass is the one failure mode this whole system exists to prevent.

3.3 · Convergence — terminating the fix loop

Standard work

ONE clean cross-family adversarial pass (a seat from a different family than the fixer, fresh on the finished diff, nothing blocking) → converged.

Trust boundary / churny run

TWO consecutive clean passes from different seats. One clean pass is a coincidence away from a miss where a miss ships.

circuit breaker

Past ~5 fix rounds, stop fixing. Adjudicate the survivors at opus max (real blocker vs reviewer theater — read the code, don't take the finding's word), escalate the real ones as needs-human. The breaker interrupts a human; it never ships silently. "Ran out of rounds" is not a ship state.

3.4 · Seat routing — the capability table as a floor

④The prompts, marked up

These are the actual agent prompts the conductor sends, adapted from v1's issue.mjs builders and the beta doctrine. Highlights mark the load-bearing clauses; the annotation strip under each says why that clause exists — most of them are scar tissue from a specific failure mode.

invariant / non-negotiable routing / mechanism anti-pattern guard UNKNOWN ≠ pass
design · dialectic · critique leg
sol · highfable · high
You designed approach A for issue #${N} independently. Here is the RIVAL
design B, produced blind by a different model family:

${designB}

Critique B against the actual codebase — Read the files it names, follow the
imports, run your own greps. Do not defer to it and do not average toward it.
Where B is right and A is wrong, say so plainly. Where B breaks a documented
decision (docs/adr/, context.md), cite the decision. Output: the strongest
version of the disagreement, not a reconciliation — the synthesizer reconciles.
invariant 1

Decorrelation preserved. Both designs are produced blind first, so the critique round adds adversarial pressure without collapsing the two views into one anchored opinion. If sol had opened and fable merely reacted, you'd never see an uncontaminated claude design.

mechanism

"Read the files, run your own greps." A critique from memory is worthless; the value is a second model actually checking the rival against ground truth. The explicit "do not average" is because the failure mode of a polite model is to split the difference and call it synthesis.

implement · per-milestone (TDD)
opus · med → xhigh
Implement milestone ${i} of issue #${N} against the plan, strict TDD
(red → green → refactor). All work in the worktree at ${WT}.

Milestone: ${milestone}

Rules:
- Failing test FIRST, minimum code to pass, then refactor. Run the project's
  test command to see red→green at each step.
- Commit this milestone atomically (conventional messages, present tense,
  NO attribution trailers, NEVER --no-verify).
- Deliver the plan's scope and nothing beyond it: no unasked-for abstractions,
  files, flags, or error handling for cases that cannot happen.
- Do the work yourself. Do NOT spawn subagents — you are one leaf of a
  fan-out and this worktree is shared with sibling agents.
- Structural deviation from the plan → note it; local deviation → adapt and
  note it in the commit message, keep going.
anti-pattern

Scope + sub-delegation guards. Opus-5-class models expand scope and can spawn a second fan-out under a shared worktree — two agents editing one file is a merge conflict with extra steps. Both are cheaper to forbid here than to catch in review (each costs a fix round).

git invariant

No trailers, no --no-verify. Enforced structurally too — a PreToolUse hook fires on the subagent's tool calls, because the SessionStart charter reaches only the main session. The prose is belt; the hook is braces.

routing

Effort per milestone. This is the dial v1 can't turn — it routes one difficulty verdict across the whole implementation. Here a mechanical milestone gets medium (reads the plan literally, scopes tight) and a hard-invariant milestone gets xhigh.

review · adversarial · prove-it-or-drop-it
sol · high
Run EXACTLY this through Bash with timeout 600000 (transport holds 540s inside):
${CODEX_LOCATE} && node "$CODEX" adversarial-review --cwd "${WT}" \
    --base ${BASE} --timeout-secs 540 --effort high --model gpt-5.6-sol
<<'FOCUS'
Your job is to BREAK this change, not summarise it. For every correctness
or security claim about executable behaviour, try to write a FAILING TEST
that demonstrates the bug. A demonstrated finding is worth ten described ones.
Hunt: injection (mime/param smuggling, SQL/HTML/shell/template), TOCTOU,
panics on request-controlled input, trust-boundary leaks, silent failures.
FOCUS
.ok true → map findings mechanically (severity→severity, file→file, line→line);
a finding with a repro test is confidence 100. .ok false OR the command fails
for ANY reason → return ONE finding titled "CODEX_UNAVAILABLE: <kind>" —
an errored review must be visible as unavailable, NEVER as a clean pass.
invariant 2

Adversarial floor + demonstration fast lane. "BREAK this change" makes the seat adversarial by construction. A finding backed by a failing test is confidence 100 — it skips adjudication entirely and its fix inherits the test as the regression guard. Prose-refute stays the floor for the non-demonstrable (design flaws, missing coverage).

UNKNOWN ≠ pass

The CODEX_UNAVAILABLE husk. A transport that dies returns a schema-valid finding titled UNAVAILABLE, not an empty list. An empty list from a seat that never ran reads as "reviewed, clean" — the single most dangerous lie in the system. The workflow logs-and-drops the husk but the coverage count reflects it.

review · security (headline at a trust boundary)
opus · xhigh→ fable fallback
Review the diff (`git -C ${WT} diff ${BASE}...HEAD`) for issue #${N}.
Cite file:line. Severity floor: a reachable panic, crash, or DoS
triggerable by request-controlled input is never below medium.
Set confidence per finding (0-100: is it real — not severity).

Hunt: injection (SQL/HTML/shell/template), content-type / MIME parameter
smuggling, secret handling, authz gaps, unsafe deserialization, TOCTOU,
panics in prod paths, trust-boundary leaks.
invariant 3

Security visibility. Opus runs its own cyber classifiers; this exact prompt shape is what they sometimes decline, returning null — indistinguishable from a dead agent. So a null here retries on fable (a different classifier), and a double-null sets securityReviewUnavailable, carried all the way to the human. Absence of findings from a seat that never ran is absence of evidence.

routing

The severity floor is a routing constraint, not a style note. It stops the downstream adjudicator from dismissing a reachable panic as "low impact" — a common reviewer-theater move that the floor makes illegal.

adjudicate · the circuit breaker's judgment seat
opus · max
Adjudicate the blocking findings that survived the fix loop for issue #${N}.
For each: is it a REAL blocker (ship-stopping if merged) or reviewer theater
(style dressed as severity, already mitigated, wrong about the code)?
Read the actual code before judging — do NOT take the finding's word for it.
Findings carry a structured confidence: weigh low-confidence criticals
skeptically; do not dismiss high-confidence mediums as noise.
realBlockers → escalates to a human. Be strict about what interrupts a human.

${blockingFindings}
invariant 6

Judgment before escalation. Only adjudicated-real blockers interrupt the human. This is the reasoning seat (opus max), not the taste seat — "is this finding real or is it wrong about the code" is settled by reading the code at maximum effort, not by discrimination. This is what a raw FIX_ROUND_CAP can't do: it just gives up.

handoff · head-sync guard
sonnet · med
Final handoff for PR #${pr} — report the PR as it exists NOW.
0. HEAD SYNC FIRST — every read below is meaningless against a stale head.
   Compare local `git rev-parse HEAD` with `gh pr view --json headRefOid`.
   HARD RULE: ciStatus may be "green" ONLY when headInSync=true. If the head
   is stale or your push failed, ciStatus is "pending" or "unknown".
1. CI: read `gh pr checks` AND the statusCheckRollup. Every completed check
   successful → green. Any failure → red (name it). Anything queued → pending.
2. Closes-link: `closingIssuesReferences` must reference #${N}; repair + re-read.
If a command fails transiently, retry up to 3× with backoff; if still no
definitive result, report "unknown" — NEVER a pass you did not observe.
invariant 4

Green only on the head you judged. The infamous false-green: a repair push's CI outlives the run, and a naive read reports the previous head's green. The hard rule ties green to an observed sha match; the conductor even downgrades a claimed-green-with-stale-head to pending as belt-and-braces.

⑤Worked example — plans#1 (typed artifacts)

plans#1 is the perfect beta stress test: it inverts v1's defaults three ways at once. Design is closed (ADR 0001, "do not reopen"). Security surface is huge relative to the ~2.3k-LOC Go repo (content-type parsing, SVG serving, CSP, streamed uploads). And nearly every one of its 12 acceptance criteria is demonstrable by a failing test. v1 would run its fixed medium-bucket fabric anyway. Here's what the conductor composes.

Composition journal comment — posted before work starts
  • Design panel: SKIPPED. ADR 0001 is the plan; a blind panel against a ratified design is theater. → one decorrelated pre-flight: sol reads ADR + issue against the real seams (artifact/store.go, httpserver/server.go, cli/cli.go) and flags anything the spec gets wrong about reality before a line is written.
  • Milestone plan (opus/medium): server first (protocol/metadata → streamed store → ServeContent viewer → headers/CSP), then CLI (inference → parse/splice → json). Server first because the CLI's e2e criterion needs a live server.
  • Per-milestone effort: most milestones are transcription of an unusually complete spec → opus/medium. Two flagged hard → xhigh: the streamed store (hash-while-copy, atomic rename, race tests AGENTS.md demands) and the byte-splicer (offset-stable replacement, criterion 8's byte-identical guarantee).
  • Shadow: YES, sol at milestone checkpoints — earns its seat on the store + splicer, where an invariant broken at milestone 2 poisons everything after.
  • Review: security is the HEADLINE. Trust-boundary tripwire pre-armed → convergence requires 2 consecutive clean passes. Seats: security (opus xhigh) + adversarial (sol, prove-it) + correctness (opus xhigh) + AC check. Simplify lens dropped — spec this tight leaves no altitude to drift.
  • Red-team menu → sol: content-type param smuggling (text/html; charset=… vs exact-match ParseMediaType), SVG-with-script served inline (CSP must neuter it — criterion 5), ETag/range interaction, splice injection via the returned capability URL.

the fork question the composition surfaced

Approach item 9 resolves attachment refs "against the HTML file's directory" and validates extensions — but never confines the path. <img src="../../../etc/passwd.png"> resolves, exists, is allowlisted → gets published with the plan's TTL. The CLI runs as the user, so it's arguably authorized — but agent-generated HTML makes it an exfil channel, and the spec's out-of-scope list doesn't close the fork.

Under the beta ROE this is a genuine mid-run AskUserQuestion (a choice the human should own), not a needs-info block. The composition exercise alone caught a spec gap a blind design panel might have transcribed straight into code. Lean: confine refs under the HTML file's tree, error on escape — one filepath.Rel check; the legit use case never leaves the directory.

transport

Steps 5a–5d go through one short ad-hoc Workflow script (deterministic 4-way fan-out, worth resume). Everything else is direct Agent calls from the conductor. This is the "medium per fan-out" freedom in action.

vs v1 on the same issue

v1 spends a 3-leg design panel + fable synthesis re-deriving what ADR 0001 already decided, runs one difficulty across all five milestones, and caps fixes at 3 rounds regardless of the trust-boundary surface. Beta spends those same tokens on the second convergence pass and the shadow instead — reallocation, not inflation.

⑥Worked example — the other end: a doc fix

The same conductor, the same invariants, an issue that wants almost none of the machinery: "README says the default TTL is 30 days; it's actually 7. Fix the doc." This is where beta's ability to make a stage not exist pays for itself — v1 would still run a 2-leg design panel and a 4-lens review over a one-word diff.

Composition: single-file doc change, zero production code path, no trust boundary. → collapse the fabric.

Verify the claim is even true sol · low

Before touching the doc: is the default actually 7d? One cheap decorrelated read of the flag default in code. If the issue is wrong, that's a needs-info fork, not a silent doc edit to match a false premise.

Fix it sonnet · low

Mechanical single-line edit, atomic commit. No design panel, no milestone plan — there is no design.

One decorrelated read + AC check sol · low

Invariant 1 still holds — a different family than the one that wrote the change reads it. But it's one lens, not four: there is nothing for correctness/security/simplify to find in a doc line. Convergence: one clean pass (no trust boundary → 1× tier).

Push, PR, ledger, handoff sonnet · low

Ledger is one row (criterion: "README matches the real default" → evidence: the diff + the code default it now agrees with). Same rigor on the contract, a fraction of the fabric.

the point

Two issues, one conductor, wildly different fabrics — and every invariant held in both. plans#1 got two convergence passes and a shadow; the doc fix got one decorrelated read and skipped four stages. Neither decision came from a size bucket; both were journaled. That gap between them is the entire value proposition.

⑦The eight invariants — what the conductor may never trade

Everything above is freedom. This is the floor. The whole design is "maximal adaptivity above a fixed floor," and these eight are the floor. A composition that violates one of them is a bug, not a style.

#InvariantThe failure it prevents
1Decorrelation — every shipped diff reviewed by a different family than wrote itclaude-reviewing-claude blesses its own blind spots
2Adversarial floor — ≥1 seat prompted to REFUTE; demonstration = confidence 100confirmation-shaped review that summarizes instead of breaking
3Security visibility — a dead security seat surfaces as securityReviewUnavailablea refused classifier reads as a clean pass
4UNKNOWN ≠ pass — green only on an observed in-sync headthe false-green: CI from a stale head reported as this diff's
5Evidence per criterion — verdict + concrete pointer, vs the launch snapshot"looks done" shipping without proof; a moved AC chased silently
6Termination on evidence — clean adversarial pass, not a round counter"ran out of rounds" shipping a known-unfixed blocker
7Containment — worktree-only writes, no sub-delegation, no --no-verifyparallel agents clobbering a shared file; bypassed hooks
8Refusal routing — cross-family fallback on any seat; double-null reporteda null from classifier roulette vanishing as if the seat passed

the through-line

Six of the eight (1, 2, 3, 4, 6, 8) exist to prevent one thing: a review that never happened reading as a review that found nothing. That is the failure v1 spent 993 lines armoring against, and it's the one thing a dynamic conductor could plausibly regress — so it's the one thing beta refuses to leave to taste. Adapt everything else; never adapt these.
