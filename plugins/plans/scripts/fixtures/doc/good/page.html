Snapshot pruning moves into the backup agent

The backup agent will delete expired snapshots itself, right after each upload succeeds. The nightly prune.sh cron job goes away. Two files change on each host, and the repository format stays as it is.

This plan asks three questions. Each one sits beside the part it governs, and your response is at the end.

1 What changes

Today two jobs touch the repository every night: the agent uploads at 02:00, and cron prunes at 03:00. They share nothing but the repository lock. When an upload runs long or fails, the prune still runs, and it can delete the last good snapshot while it keeps a broken one. Observed on pve-02 on 2026-10-19: the upload ran 71 minutes, the prune ran right after it, and the newest snapshot was incomplete.

Who prunes old snapshots?

The agent change is about 40 lines and needs a new agent release on all four hosts. Keeping cron costs nothing now, but it leaves the race in Figure 1 in place. Running both for a week doubles the prune work during that week and shows whether the two agree.

2 The runbook, before and after

The runbook's pruning section changes with the job. Struck words go, underlined words are new.

3 How long snapshots live

The agent reads its retention from agent.toml. The cron script keeps 30 daily snapshots. The plan proposes 14, because no restore in the last year reached back more than 9 days.

How many daily snapshots does the agent keep?

Fewer snapshots free disk space now. More snapshots let you restore from further back. Weekly snapshots stay at 8 in every option.

4 Rollout

Each host gets the new agent release and its agent.toml, and loses its cron line. A host can go back by restoring both files.

Which hosts move in the first week?

Hosts that move first test the change for the others. A host that waits keeps the race for one more week.

5 What stays the same

  • The repository format, its encryption key and its path.
  • The upload schedule, 02:00 on every host.
  • Weekly snapshots: 8 are kept.
  • Restore commands. A restore never reads agent.toml.
