The collector and its spool

2026-10-26

The collector reads every journal on the host, batches lines into one spool file per minute, and ships each closed file to the store. Measured on a four-core host with the default batch size. A file that fails to ship stays in the spool until the next pass.

The spool

Each file is named after the minute it covers, so a restart picks up where it stopped. The store answers each upload with a digest, and the collector deletes a file only after that digest matches its own.

Why not ship each line as it arrives?

One request per line costs a round trip per line. At a few thousand lines a second, the store spends its time on headers.

for line in journal: post(store, line)   # one round trip per line, thousands per second
